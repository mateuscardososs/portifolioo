Case técnico principal

Sistema usado em operação real

Controle de Acesso

Sistema full stack para gerenciar colaboradores, convidados, áreas, dispositivos e eventos de acesso em uma operação de grande porte.

Contexto

Uma operação com pessoas, áreas e dispositivos

O projeto nasceu para organizar cadastros e permissões de acesso, acompanhar dispositivos e registrar eventos em uma operação real.

Projeto desenvolvido individualmente. Modelei os dados, construí backend e interfaces e implementei autenticação, gestão de pessoas, fluxo de visitantes, processamento de fotos, mensageria e atualização em tempo real.

Decisão

Integração desacoplada do fluxo principal

A integração com as controladoras fica atrás de uma abstração de provider. Assim, o desenvolvimento pode usar um provider simulado sem hardware, enquanto a operação habilita o provider real por configuração.

RabbitMQ desacopla a sincronização do fluxo principal, e WebSocket atualiza a interface. A separação adiciona componentes à execução, mas evita bloquear cadastros durante a comunicação com dispositivos.

Estado da integração Intelbras

Provider real validado em controladora Intelbras via CGI com autenticação Digest.
Modo fake mantido como padrão de desenvolvimento.
A compatibilidade depende do modelo e do firmware da controladora.

Evidência

O que pode ser validado no repositório

  • 279 testes JUnit no backendCobrem autenticação, RBAC, cadastros, dispositivos, eventos, fotos e integração Intelbras.
  • Roteiro local documentadoDocker Compose para infraestrutura, Maven para a API e npm para o frontend.
  • Smoke test reproduzívelCriação de área, dispositivo e colaborador, seguida da simulação de um evento.
  • Compose de produçãoBackend, frontend, PostgreSQL, RabbitMQ, proxy, Prometheus e Grafana.

Testes executáveis localmente com Maven; workflow público de CI ainda não configurado.

Resultado

Entregue para uso real

O sistema foi utilizado em um evento real para apoiar o cadastro e a gestão operacional de acessos.
